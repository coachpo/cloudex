# 0006 双渠道 Codex 网关与可丢弃的容器

- 状态：已接受
- 日期：2026-11-27

## 背景

[C-001](../../CONSTRAINTS.md#c-001-codex-容器可随时丢弃) 要求容器替换无需保留原 home 或运行身份。管理员要从同一个控制面分别连接本人的 Codex 和 ChatGPT 授权。两渠道的注册、身份、模型能力和路由不同。若由容器持有上游 refresh token，替换容器可能丢失轮换后的唯一凭据，多实例共享该 token 还会竞争刷新。

## 决定

- 每个 Workspace 持久保存一项可空绑定。控制面作为上游令牌的唯一持有者，按授权协调刷新。一份授权可被多个 Workspace 使用，各自使用限定于本次运行实例和绑定版本的凭据。
- 容器 home 随实例更换从镜像初始化，项目卷和 SSH 主机身份保持独立。新运行实例通过归属 Host 获取网关凭据，绑定和授权代次划定各自的 Codex 会话空间。
- 变更绑定的事务提交为转发权切换点，单进程控制面协调远端写入和本地提交。已交给网络的上游请求保留其原归属。新绑定使用自身目录和上下文。
- 两个适配器均优先用上游 WebSocket，给明确的生成前 Upgrade 拒绝保留同授权、同模型 HTTP/SSE 回退。生成可能已送达时保留提交归属，拒绝自动重放。
- Workspace 容器直接连接控制面的推理入口。Agent 和 SSH 直连共用这条推理路径，使两种 Host 都能使用托管授权，无需各维护一套推理转发。默认 Compose 使用本机 Docker 私网内的 HTTP 入口，管理监听继续留在管理网络，推理端口不发布到宿主机。远程 Host 和自定义入口使用容器信任且可达的 HTTPS。

## 后果

控制面重启会终止进行中的连接。实例凭据需要按 Host 实况核对后恢复使用。轮换落盘和生成受理失去确认时，偶尔需要重新授权或主动发起新运行。这样可避免重复兑换旧 refresh token 或重复提交原有生成。[生命周期和恢复](../workspace-lifecycle.md#codex-授权和运行实例) · [转发契约](../codex-gateway.md#流式转发)
